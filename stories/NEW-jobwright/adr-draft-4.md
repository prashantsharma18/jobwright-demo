# 0004 · The API contract: contract first, one error format

## For the reviewer
- **Asked of:** The tech lead or architect (the decider), to accept the decision with the design; consumers agree a contract change
- **Record it:** On the Status line (Accepted at design approval), and on the work item with the design's version and commit
- **Tier and main risk:** 3: the web app and the API drifting apart, or errors that leak internals
- **Changed since the last version:** first version

Status: Accepted at design approval (approved by Prashant Sharma, decider, 2026-11-09)
Decider: Prashant Sharma (tech lead) · Agreed: Prashant Sharma (owner of the API and of the web app, its only consumer) · Work item: NEW-jobwright · Tier: 3

## Context
Requirements section 8 requires contract tests: "the API's published contract is the source, and the web client is
generated from it". NFR-SEC-02 and 03 require one machine-readable error format (RFC 9457) that reveals nothing.
aidlc works contract first: the contract and its failing tests exist before the code.

## Drivers
- Section 8, contract tests: the web cannot drift from the API.
- NFR-SEC-03: RFC 9457 for every client, whatever it asks to accept (AC13).
- AC4: another tenant's record gets exactly the not-found answer.
- No second contract tool to run and keep (memory and dependency limits, requirements 9.5).

## Options
A. Design first: `api/contract/openapi.yaml` (OpenAPI 3.1) is written by hand and committed; a provider test fails
   when the API's own generated document differs from it; a breaking-change check compares it with the last
   release's; the web client's types are generated from it — **chosen**.
B. Code first: CI generates the document from the API and commits it — rejected: the cheapest, but the contract
   then follows the code, which is what contract first forbids.
C. Consumer-driven contracts with a broker — rejected: one consumer in the same repository, and a broker is a new
   service to run.

## Decision
- The contract is `api/contract/openapi.yaml`, version 1 drafted in `stories/NEW-jobwright/contract/openapi.yaml`.
  It changes only through `aidlc-design` (amendment mode).
- Provider: the API publishes its document at `/openapi/v1.json` from the framework's built-in generator; the test
  `ContractDocumentTests` compares it, normalised, with the committed file. If the generator cannot express part of
  the contract, the test reports the difference and the design decides; the build does not edit the contract.
- Breaking changes: `oasdiff` (pinned in `new-system.md`) compares the contract with the one at the last release tag;
  a breaking change fails CI unless the path version changes (`/v2`), done by expand and contract.
- Consumer: the web app's types are generated by `openapi-typescript` and called through `openapi-fetch`; the
  consumer tests run in the same CI run as the provider tests.
- Versioning: the path carries the major version (`/v1`). New optional fields and new endpoints are minor.
- Errors: every error is `application/problem+json`, with `type` from a closed list under
  `https://jobwright.example/problems/` (`invalid`, `not-found`, `forbidden`, `membership-revoked`,
  `unauthenticated`, `rate-limited`, `unavailable`, `server-error`). The framework's content negotiation is not used
  for errors: a handler writes the problem whatever the request accepts. No exception text, type name, SQL or path is
  ever written to a response.
- Lists are paginated (`page`, `pageSize` up to 100) and return `{ data, pagination }`.
- No endpoint in increment 1 changes state through the API, so no idempotency key is needed yet; the first one that
  does carries one (designing-apis).

## Consequences
- The API cannot drift from the contract — enforced by `ContractDocumentTests` (required check).
- The web app cannot drift from the contract — enforced by the generated types and the consumer tests (required check).
- A breaking change fails CI — enforced by the `oasdiff` step (required check).
- A response that leaks internals fails CI — enforced by `ProblemFormatContractTests` (AC13).
- Revisit if a consumer outside `jobwright-app` appears: it then agrees each new version (this ADR's Agreed line grows).
